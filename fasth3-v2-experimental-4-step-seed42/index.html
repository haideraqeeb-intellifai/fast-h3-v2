Exact schedule and configuration

The published eight-forward ladder is [999, 874, 749, 624, 500, 375, 250, 125]. This experiment takes every other rung: [999, 749, 500, 250], followed by terminal zero. Five sigma-grid points produce exactly four transformer forwards. Video/audio shifts remain 10/3.

The official eight-step entrypoint rejects this override. A separate local model view links the unchanged original weights and carries an explicitly marked experimental schedule. The original model contract remains intact. This is neither an official four-step recipe nor a separately distilled four-step checkpoint.

What changed in decoder memory handling?

Before GPU upload, the patched decoding stages retain references to their original CPU parameter and buffer storage. After decoding, they restore those CPU references and discard the GPU copies. They do not call vae.to("cpu") or audio_vae.to("cpu"). The CPU originals are immutable during inference. CPU-to-GPU weight loading and generated pixel/audio transfers to CPU still occur.

This local inference-only patch is additional to the official FastVideo runtime. It does not change weights, precision, denoising, or decode arithmetic. Both decoders log zero weight copy-back bytes for both requests. In the measured request, restoring CPU references and releasing GPU weights took 0.853 ms for video and 0.987 ms for audio (host wall time for the release helper). A small GPU test verified that release restores the original CPU storage and executes no tensor-copy operators. The original CPU weight storage remains alive during GPU decoding: video VAE 9.70 GiB, audio VAE 0.56 GiB. The GPU copies are still freed before the next stages/requests. The patch and logs are included below.

Does V2 support Ref2VA?

No supported distilled Ref2VA mode is provided by this checkpoint. The official model card states that it supports text-to-audio-video and that FL2VA and Ref2VA were not distilled. FastVideo has Ref2VA code, but this checkpoint's modular index points its transformer_ref component to MiniMaxAI/MiniMax-H3. Using that component would use the base model's reference transformer, not V2's distilled text-to-audio-video transformer. No Ref2VA generation was attempted.
